# UR-Fashion Production Launch QA

## Environment
- `SUPABASE_URL`: live Supabase project URL.
- `SUPABASE_ANON_KEY`: publishable/anon browser key only.
- `NEXT_PUBLIC_SUPABASE_URL`: same value for hosts that read Next-style public env names.
- `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`: same public key value.
- Never expose a Supabase service-role key in frontend env files.

## Build and Runtime
- Build: `npm run build`
- SSR server: `npm run serve:ssr:app`
- Runtime config is generated by `scripts/write-runtime-config.mjs` before dev/build/SSR commands.
- `.env.local` is ignored by git; keep production values in the deployment platform secret/env UI.

## Supabase Setup
- Apply base files: `schema.sql`, `rls-policies.sql`, `storage.sql`, `seed.sql`.
- Apply phase migrations in order:
  `phase-2a-orders-migration-recommendations.sql`,
  `phase-3-checkout-guest-rpc.sql`,
  `phase-3a-fix-orders-cod-nullability.sql`,
  `phase-4-auth-security-rls.sql`,
  `phase-5-order-tracking-rpc.sql`.
- Reload PostgREST after SQL changes with `notify pgrst, 'reload schema';`.
- Create public storage bucket `product-images` and upload paths referenced by catalog records.

## E2E Regression Plan
- Guest checkout creates one order and matching order items, then clears cart only after success.
- Login/logout updates header identity and preserves session after refresh.
- Admin can view orders, open detail, and update status.
- Customer can view only their own `/orders` and `/orders/:id`.
- Wishlist merges guest local items into Supabase after customer login and remains user-scoped.
- Order tracking returns a public-safe card for valid order number + phone and safe not-found for wrong phone/order.
